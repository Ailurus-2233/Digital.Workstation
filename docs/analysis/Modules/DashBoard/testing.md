# DashBoard — 验证方式

按 [仓库验证约定](../../../agents/verification.md) 在本机启动应用手动验收。本模块没有自动化测试验收要求；以下是操作步骤，未表示已通过。

## 正常启动与贡献显示

1. 在仓库根运行 `dotnet run --project Launcher/Launcher.csproj -c Debug`。
2. 观察启动台依次显示核心服务、模块名与 `i/N`、就绪，随后关闭并显示主窗口。Ready 发布前已完成贡献与 Shell 准备。
3. 状态栏显示“启动台”，位于“就绪”之后。ActivityBar 顶部与 BottomPanel 没有已删除的 DashBoard 演示工具视图。

## 模块失败与继续/退出

本组需在临时诊断模块中注入故障，完成后撤销诊断代码，不保留演示贡献。

1. 分别让模块初始化和已登记贡献工厂抛异常。启动台均应显示当前模块及错误详情；主窗口尚未出现。
2. 点击“继续”：下一条进度应清除失败态；工作区中没有失败批次登记的贡献，正常模块贡献仍存在。若后续模块声明依赖失败模块，应先呈现该依赖失败，不能继续初始化它。
3. 再启动并触发同一故障，点击“退出”：应用结束，不出现主窗口。
4. 若失败模块是 DashBoard 自身，启动台仍能承载失败决策，因为窗口在模块加载前已创建；继续后状态栏不出现其“启动台”贡献。

检查范围是贡献可见性与启动决策，普通 DI 注册、事件订阅和任意模块副作用不由贡献批次回滚。批次实现与故障注入位置见 [Framework/testing.md](../../Core/Framework/testing.md)。

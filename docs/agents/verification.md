# 验证约定

本工作流不用自动化测试做验收。每个实现片段完成后，agent 停下来给出手动验证步骤，由用户实际运行程序确认。

## 项目类型

纯桌面端（Avalonia + Prism 跨平台工具箱），不依赖任何硬件、PLC、串口、总线或仿真器。

- 验证只需在本机启动应用、操作界面即可。
- 生成验证步骤时不得包含连接设备/仿真器一类前提。

## 启动方式

以仓库根 `README.md` 的「构建与运行」一节为准；当前为：

    dotnet run --project Launcher/Launcher.csproj -c Debug

也可在 Visual Studio / Rider 中 F5 启动 Launcher 项目。

## 验证时观察什么

- 应用界面本身：启动台（DashBoardWindow）进度 → MainWindow 出现、模块加载结果
- Serilog 控制台输出：启动日志、模块加载进度、异常堆栈

## Agent 生成验证步骤的约定

- 每个实现片段完成后，给出可逐步执行的手动验证步骤：启动命令 → 操作路径 → 预期界面/日志表现。
- 步骤须具体到操作（点哪个菜单、看哪个窗口/哪行日志），不写「确认功能正常」一类空话。
- 用户反馈验证结果前，不宣称完成。

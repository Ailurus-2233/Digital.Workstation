# 启动台与逐模块异步启动序列

## 状态

已接受

## 上下文

Prism 默认在应用初始化阶段同步加载全部模块。模块加载期间主窗口尚未就绪，用户无法看到进度；单个模块失败时也缺少在界面上决定继续或退出的入口。启动器在 Avalonia 启动前负责程序集与 native 资产解析，框架启动序列负责 Avalonia 启动后的模块生命周期，两者应保持边界清晰。

## 决策

1. `FrameworkApplication<TWindow>.OnFrameworkInitializationCompleted` 不直接调用 Prism 的同步模块初始化，而是启动异步流程。
2. 流程依次经过 `CoreServices`、`LoadingModules`、`Ready` 三个阶段：初始化核心服务并显示启动台；逐模块加载并发布进度；关闭启动台并显示主窗口。
3. 每个阶段通过 `StartupProgressEvent` 向启动台报告阶段、模块名称和 `i/N` 进度；模块异常通过 `ModuleLoadFailedEvent` 报告。
4. 启动台对模块失败提供“继续（跳过该模块）”与“退出”两种选择。继续时流程进入下一个模块，退出时关闭应用。
5. `Launcher` 的程序集/native 引导不纳入上述进度范围；它必须在 Avalonia 类型大量加载前完成。

## 后果

- 启动过程对用户可见，模块加载进度和失败决策集中在启动台。
- 主窗口只在模块加载完成或用户选择跳过失败模块后进入桌面生命周期。
- 框架需要维护异步启动状态与事件契约；启动台需要订阅进度、失败和决策回传事件。
- 启动器与框架的职责边界明确：前者准备运行时依赖，后者管理应用模块生命周期。
